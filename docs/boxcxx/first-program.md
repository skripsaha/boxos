# Первая программа на C++ для BoxOS

## Назначение

Руководство описывает создание простой команды внутри исходного дерева
BoxOS: исходник, подключение к сборке, включение в образ и запуск из
оболочки. Пример печатает строку с вычисленным числом и завершает работу.

Программа собирается на основной системе кросс-компилятором для x86-64.
BoxCxx предоставляет собственные заголовки стандартной библиотеки и среду
выполнения C++; BoxLib — интерфейс к BoxOS и стартовый код. Обычная сборка
системным компилятором с библиотеками основной системы для этого не подходит.

Команды ниже выполняйте в корне репозитория, если явно не указано другое.
Имя `hello` используется для учебной команды; перед добавлением убедитесь,
что оно не занято другой программой вашего дерева.

## Инструменты

Для сборки нужны GNU Make, NASM, Python 3, компилятор C основной системы
для вспомогательных инструментов и кросс-инструменты `x86_64-elf-*`.
Для запуска нужен `qemu-system-x86_64`.

Проверьте наличие основных инструментов:

```sh
make --version
nasm -v
python3 --version
gcc --version
x86_64-elf-gcc --version
x86_64-elf-g++ --version
x86_64-elf-ld --version
x86_64-elf-ar --version
x86_64-elf-as --version
x86_64-elf-objcopy --version
x86_64-elf-nm --version
x86_64-elf-objdump --version
x86_64-elf-readelf --version
qemu-system-x86_64 --version
```

Правила C++ используют `-std=gnu++23`. Кросс-компилятор должен поддерживать
этот режим и возможности, используемые текущей версией BoxCxx. Список команд
проверяет доступность инструментов; совместимость всей цепочки проверяет
сборка. Цель `make check-deps` проверяет часть зависимостей, но не заменяет
проверку C++-компилятора и сборку программы.

Установка инструментов зависит от основной системы. Не подменяйте
`x86_64-elf-g++` командой обычного `g++`: целевая платформа и подключаемые
библиотеки должны соответствовать правилам проекта.

## Исходник

Создайте файл `src/userspace/utils/hello.cpp`:

```cpp
#include <print>

#include "box/form.h"

BOX_FORM("");

int main()
{
    constexpr int Answer = 6 * 7;
    std::println("Hello, BoxOS! Answer: {}", Answer);
    return 0;
}
```

`<print>` берётся из BoxCxx. `std::println()` форматирует строку, добавляет
перевод строки и передаёт результат в консольный канал BoxOS. Для первого
примера используется ASCII, чтобы проверка запуска не зависела от
возможностей отображения символов выбранным шрифтом.

`BOX_FORM("")` объявляет Form без входных полей. Макрос самостоятельно
добавляет заголовок `form` и помещает декларацию в секцию
`.boxos.form`; писать эту строку внутри аргумента не нужно. Разместите одну
декларацию Form на программу на уровне файла, вне `main()`.

### `main`

**Краткое описание:** Выведите приветствие с вычисленным числом и завершите программу.

**Параметры:** Нет; сигнатура примера — `int main()`.

**Возвращает:** `int`: `0` при нормальном завершении примера.

**Побочные эффекты:** Форматирует и выводит строку через консольный канал; форматирование может выделять память.

**Как работает:** Стартовый код `boxlib_start.o` предоставляет `_start`, подготавливает стек, запускает глобальные конструкторы и вызывает `main()`. Возврат из `main()` передаёт код завершения в `exit()`, который выполняет финализацию среды и завершает процесс. Локальные объекты уничтожаются при обычном выходе из функции по правилам C++.

**Примечания:** Стартовый код не передаёт слова команды как обычные `argc`/`argv`: он устанавливает `argc = 0`, `argv = nullptr`. Для входных данных программы используйте Form; низкоуровневое представление запуска доступно через Luggage. Пример не принимает входных данных. Гарантии обычного завершения не распространяются на аварийное или принудительное прекращение процесса.

**Типичное применение:** Используйте пример для проверки цепочки сборки и запуска перед добавлением работы с файлами, вводом или Painter.

**Пример:** Полная единица трансляции приведена в разделе «Исходник».

## Подключение к сборке утилит

Измените `src/userspace/utils/Makefile` в двух местах.

Добавьте `hello` в существующую переменную `UTILS`. Не создавайте второе
присваивание `UTILS =`, которое затрёт список. Допустимо добавить отдельную
строку после существующего списка и до цели `all`:

```make
UTILS += hello
```

Затем добавьте отдельное правило линковки рядом с правилами C++-утилит:

```make
hello.elf: $(BOXLIB_START) hello.o $(BOXCXX) $(BOXLIB) $(BOXLIB_DIR)/user.ld $(NAMEPLATE_TOOL)
	$(call NameplateLink,$(CXX),$(LDFLAGS),$(BOXLIB_START) hello.o $(BOXCXX) $(BOXLIB) -lgcc)
```

Строка рецепта должна начинаться символом табуляции. Существующее правило
`%.o: %.cpp` скомпилирует `hello.cpp` с `$(CXXFLAGS)`; отдельное правило
компиляции для одного файла не требуется.

Общее правило `%.elf` предназначено для C и не подключает BoxCxx. Поэтому
для этой программы нужен явный вызов `$(CXX)` с `$(BOXCXX)` перед `$(BOXLIB)`:
статические библиотеки разрешаются с учётом порядка, а BoxCxx использует
функции BoxLib. `-lgcc` подключает необходимые вспомогательные функции
кросс-компилятора. Среду C++ предоставляет `libboxcxx.a`; системные
`libstdc++` и `libc++` здесь не подключаются.

`NameplateLink` из `src/userspace/nameplate.mk` выполняет два прохода
линковки: получает адреса функций, добавляет таблицу имён и проверяет,
что адреса не изменились. Сохраните этот механизм: таблица нужна для
диагностики работающей программы.

### Флаги и библиотеки

Используйте готовые `CXXFLAGS` и `LDFLAGS` из Makefile. Их существенные части:

| Настройка | Назначение |
|---|---|
| `-std=gnu++23` | Выбор принятого в проекте режима C++. |
| `-nostdinc++` и пути `boxcxx/include/std`, `boxcxx/include` | Подключение заголовков BoxCxx вместо стандартной библиотеки основной системы. |
| `-ffreestanding`, `-nostdlib` | Сборка без автоматически подключаемой среды обычного приложения основной системы. |
| `-fexceptions`, `-frtti`, `-fcoroutines` | Включение используемых проектом механизмов языка. |
| `-fuse-cxa-atexit`, `-fasynchronous-unwind-tables` | Регистрация завершения объектов и данные для раскрутки стека. |
| `-fpie`, `-Wl,-pie`, `-Wl,--no-dynamic-linker` | Позиционно-независимый образ без внешнего динамического загрузчика. |
| `-T $(BOXLIB_DIR)/user.ld` | Раскладка секций, стартовая точка и данные среды выполнения по правилам BoxOS. |
| `$(BOXLIB_START)` | Реализация `_start`, вызывающая среду выполнения и `main()`. |
| `$(BOXCXX) $(BOXLIB) -lgcc` | Среда C++, интерфейс BoxOS и вспомогательные функции компилятора. |

Это пояснение, а не замена полного списка флагов: сохраняйте также
настройки защиты и соглашений вызова из существующего Makefile.
Painter для текстового приветствия не требуется. Для программы,
использующей Painter, существующие правила размещают `$(PAINTER)` перед
`$(BOXCXX) $(BOXLIB)` и добавляют его в зависимости цели.

## Добавление в образ системы

Измените корневой `Makefile` в двух местах.

Добавьте `hello` в существующий список `UTIL_NAMES`. Он определяет
`UTIL_ELFS`, которые собираются перед созданием образа. Если используете
отдельное дополнение, поставьте его непосредственно после списка
`UTIL_NAMES`, перед вычислением `UTIL_ELFS`:

```make
UTIL_NAMES += hello
```

Внутрь существующего многострочного значения `VOLUME_CONTENT` добавьте
пару «файл и теги»:

```make
	$(UTILS_DIR)/hello.elf "utility,example" \
```

Это строка внутри значения переменной, а не отдельный рецепт. Разместите
её среди других утилит и сохраните обратные косые черты, продолжающие
список. `utility` обозначает запускаемую программу, `example` —
дополнительный тег примера.

Корневая сборка преобразует указанное в `VOLUME_CONTENT` имя ELF в
`build/box/hello.box` и передаёт на том упакованный файл. Для упаковки
используется `build/pack`, собираемый из `tools/pack.c`. Редактировать
правила упаковки или вручную заменять `.elf` на `.box` в
`VOLUME_CONTENT` не требуется.

Три списка решают разные задачи:

| Место | Задача |
|---|---|
| `src/userspace/utils/Makefile`: `UTILS` и правило `hello.elf` | Собрать и слинковать утилиту. |
| Корневой `Makefile`: `UTIL_NAMES` | Включить её в зависимости общей сборки утилит. |
| Корневой `Makefile`: `VOLUME_CONTENT` | Упаковать программу и разместить на томе с заданными тегами. |

Одного исходника или готового `hello.elf` недостаточно для появления
команды в загружаемой системе.

## Сборка и запуск

Завершите уже запущенный экземпляр QEMU перед пересозданием его дискового
образа. Следующая команда очищает результаты сборки и создаёт новый
`build/boxos.img` из состава репозитория; данные, созданные только внутри
предыдущего образа, в новый образ не переносятся.

Из корня репозитория выполните:

```sh
make clean && make && make run
```

Первая сборка создаёт BoxLib, BoxCxx, программы, упаковщик, загрузчики и
образ системы. Запуск по умолчанию использует QEMU, одно ядро и `512M`
оперативной памяти. Дождитесь приглашения оболочки BoxOS и введите:

```text
hello
```

Ожидаемый вывод программы:

```text
Hello, BoxOS! Answer: 42
```

После завершения программы оболочка снова должна принять команду.
Имя команды вводится без расширения: на томе лежит `hello.box`, а оболочка
распознаёт программу по её имени и тегу `utility`.

После изменения исходника снова выполните последовательность сборки и
запуска. Если весь проект уже собран и требуется проверить только
компиляцию и линковку утилиты, доступна команда:

```sh
make -C src/userspace/utils hello.elf
```

Она предполагает наличие стартового объекта и библиотек от общей сборки.
Она обновляет ELF, но сама по себе не пересоздаёт `.box` и загружаемый
образ; для проверки внутри BoxOS используйте общую сборку и запуск.

## Проверка результатов

После успешной общей сборки должны существовать:

| Файл | Содержимое |
|---|---|
| `src/userspace/utils/hello.o` | Объектный файл учебной программы. |
| `src/userspace/utils/hello.elf` | Слинкованный ELF с Form и Nameplate. |
| `build/box/hello.box` | Программа в формате загрузки BoxOS. |
| `build/boxos.img` | Дисковый образ с программой на томе. |

Для проверки ELF на основной системе выполните:

```sh
x86_64-elf-readelf -h src/userspace/utils/hello.elf
x86_64-elf-readelf -p .boxos.form src/userspace/utils/hello.elf
tools/nameplate verify src/userspace/utils/hello.elf
```

Заголовок ELF должен указывать x86-64 и тип `DYN` для используемой схемы
статического PIE. Секция `.boxos.form` должна начинаться строкой `form`.
Проверка Nameplate должна завершиться успешно. Эти проверки подтверждают
структуру файла; вывод строки и возврат в оболочку проверяются запуском.

## Возможные ошибки

| Симптом | Что проверить |
|---|---|
| `x86_64-elf-g++: command not found` | Доступность кросс-компилятора в `PATH`. |
| Не найден `<print>` или используются заголовки основной системы | Сборку через правило `%.cpp` с `$(CXXFLAGS)` и путями BoxCxx. |
| `undefined reference` к функциям среды C++ | Явное правило `hello.elf`, наличие `$(BOXCXX)` и порядок библиотек. |
| `undefined reference to main` | Наличие `int main()` и `hello.o` в аргументах линковки. |
| GNU Make сообщает `missing separator` | Табуляцию в начале строки рецепта и расположение строки `VOLUME_CONTENT`. |
| ELF собран, но команда не найдена | Все записи в списках сборки и образа, тег `utility`, пересоздание образа и запуск нового экземпляра системы. |
| После изменения программы вывод остался прежним | Успех общей сборки и использование нового `build/boxos.img`, а не продолжающего работать старого экземпляра QEMU. |
