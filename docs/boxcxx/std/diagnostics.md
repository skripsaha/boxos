# Диагностика

## Назначение

Проверки, сигналы, коды ошибок, трассировка стека и отладка в BoxOS.

Главное отличие от Unix: **BoxOS никогда сама не посылает процессу
сигналов**, а ошибки системы приходят значением `box::error`
([error](../native/error.md)), а не через errno. Диагностика стандартной
библиотеки пишется на экран: вывод только в последовательный порт на
реальной машине без кабеля никто бы не увидел.

## Проверки

### `assert` (`<cassert>`)

**Краткое описание:** Проверяет условие и завершает программу при нарушении.

**Параметры:** Одно выражение (как в стандарте; аргумент шаблона берите в скобки: `assert((std::is_same_v<A, B>))`).

**Возвращает:** `void`.

**Побочные эффекты:** При нарушении: две строки на экране (выражение; файл, строка, функция) и `std::abort` — без `atexit` и статических деструкторов.

**Примечания:** Заголовок без защиты от повторного включения — по стандарту: `assert` переопределяется по текущему `NDEBUG` при каждом включении.

**Пример:**
```cpp
#include <cassert>
#include <vector>

int First(const std::vector<int> &Values)
{
    assert(!Values.empty());
    return Values.front();
}
```

## Сигналы

### `std::signal` / `std::raise` (`<csignal>`)

**Краткое описание:** Установка обработчика и доставка сигнала самому себе.

**Параметры:** Как в стандарте; сигналы `SIGINT` 2, `SIGILL` 4, `SIGABRT` 6, `SIGFPE` 8, `SIGSEGV` 11, `SIGTERM` 15.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** `raise` вызывает обработчик в текущей нити сейчас.

**Как работает:** Асинхронной доставки нет — по решению: у BoxOS есть свой язык событий (Touch, [touch](../native/touch.md)). Работает то, что требует стандарт: установка, `raise`, значения по умолчанию. Смерть по умолчанию — код выхода 128 + номер сигнала. Обработчик после срабатывания не сбрасывается в `SIG_DFL`. Таблица обработчиков одна на процесс, ячейки атомарные.

**Примечания:** Просьба завершиться (Ctrl+Alt+End) приходит не сигналом, а событием: `painter::tui::EventKind::EndAsked`, `painter::gui::Event::Kind::EndAsked`, `READLINE_ASKED_TO_END`. Реакция ядра на событие — `box::reflex` ([reflex](../native/reflex.md)).

**Пример:**
```cpp
#include <csignal>
#include <cstdio>

extern "C" void OnTerm(int) { std::puts("прошу завершиться"); }

int main()
{
    std::signal(SIGTERM, OnTerm);
    std::raise(SIGTERM);   // вызовет OnTerm сейчас
    return 0;
}
```

## Коды ошибок

### `<cerrno>` / `<system_error>`

**Краткое описание:** errno есть для кода C, но система его не устанавливает; `std::error_code` связан с ошибками BoxOS честно.

**Параметры:** Как в стандарте.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** Нет.

**Как работает:** Регистра errno в BoxOS нет: boxlib возвращает `error_t` из вызова, который не удался, `box::error` несёт его в C++. `errno` устанавливают только функции библиотеки C, которым это предписывает стандарт C (например, `strtol` при переполнении). `box::errc` подключается к `std::error_code` своей категорией `"box"` со своей нумерацией — код BoxOS никогда не выдаётся за POSIX-код ([error](../native/error.md)).

**Пример:**
```cpp
#include <system_error>

#include "box/cxx/error.h"

bool OutOfMemory(std::error_code Ec) { return Ec == box::errc::no_memory; }
```

## Трассировка стека

### `std::stacktrace` (`<stacktrace>`)

**Краткое описание:** Трассировка стека с именами функций.

**Параметры:** Как в стандарте.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** `current()` обходит стек; `description()` демангует имя (выделяет память).

**Как работает:** Таблица имён (Nameplate) создаётся при линковке из символов образа и вкладывается в него, поэтому назвать адрес — двоичный поиск в своей памяти: без системного вызова, выделения и блокировок. Имена хранятся декорированными и демангуются по запросу (около 93 % — байт в байт как libiberty; при отказе печатается декорированное имя).

**Примечания:** Имени файла и номера строки нет.

**Пример:**
```cpp
#include <print>
#include <stacktrace>

void WhereAmI() { std::println("{}", std::stacktrace::current()); }
```

## Отладка

### `std::breakpoint` / `std::breakpoint_if_debugging` / `std::is_debugger_present` (`<debugging>`)

**Краткое описание:** Точка останова и проверка наличия отладчика (C++26).

**Параметры:** Нет.

**Возвращает:** `is_debugger_present` — (`bool`), в BoxOS всегда `false`: протокола подключения отладчика нет.

**Побочные эффекты:** `breakpoint()` выполняет `INT3`; без отладчика ядро завершает программу (как неперехваченный `SIGTRAP` в других системах). `breakpoint_if_debugging()` ничего не делает.

**Примечания:** `breakpoint_if_debugging()` безопасно оставлять в готовом коде; голый `breakpoint()` — нет.

**Пример:**
```cpp
#include <debugging>

void Check(bool Bad) { if (Bad) std::breakpoint_if_debugging(); }
```
