# Параллельность

## Назначение

Как потоки выполнения и синхронизация C++ устроены в BoxOS.

`std::thread` — это **нить** (strand): дополнительный контекст выполнения
в кабине программы — общее адресное пространство, свой стек. Запуск
программы целиком — другое: новая кабина ([process](../native/process.md),
[child](../native/child.md)). Собственный интерфейс нитей с ожиданием в
деструкторе и наблюдением — `box::strand` ([strand](../native/strand.md)).

Все примитивы синхронизации (`mutex`, `condition_variable`, `atomic` и
прочие) действуют внутри одной кабины. Для синхронизации между кабинами —
атомарные операции над общей памятью Bay ([bay](../native/bay.md)) и
`box::park`/`box::wake` ([strand](../native/strand.md)).

## Нити

### `std::thread` / `std::jthread`

**Краткое описание:** Запускают нить в кабине программы.

**Параметры:** Как в стандарте.

**Возвращает:** Неприменимо: классы.

**Побочные эффекты:** Создают нить (`strand_spawn`); бросают `std::system_error`, если у ядра нет места.

**Как работает:** Ожидание (`join`) — сон на флаге в куче через `park`/`wake` ядра, без опроса. TLS нити создаёт ядро до её первой инструкции; деструкторы `thread_local` выполняются при её окончании. `get_id()` — pid нити ядра. Исключение, вылетевшее из функции нити, — `std::terminate`.

**Примечания:** Без FSGSBASE ядро отказывает в нитях — тогда `std::thread` бросает исключение, а параллельные алгоритмы работают в вызывающей нити. Планирования отдельной нити нет: доля процессора — свойство кабины (теги процесса).

**Пример:**
```cpp
#include <numeric>
#include <thread>
#include <vector>

long Sum(const std::vector<int> &Data)
{
    long Left = 0, Right = 0;
    const auto Middle = Data.begin() + static_cast<long>(Data.size() / 2);
    std::thread Worker([&] { Left = std::accumulate(Data.begin(), Middle, 0L); });
    Right = std::accumulate(Middle, Data.end(), 0L);
    Worker.join();
    return Left + Right;
}
```

### `std::thread::hardware_concurrency`

**Краткое описание:** Возвращает число ядер, способных выполнять программы параллельно.

**Параметры:** Нет.

**Возвращает:** (`unsigned`) число ядер приложений (App-Cores) из сведений системы; 0 — неизвестно.

**Побочные эффекты:** Системный вызов.

**Примечания:** Ядра системы (K-Cores) не считаются: они выполняют работу ядра ОС, а не программ.

**Пример:**
```cpp
#include <thread>

unsigned Workers() { return std::max(1u, std::thread::hardware_concurrency()); }
```

### `std::this_thread::sleep_for` / `sleep_until` / `yield` / `get_id`

**Краткое описание:** Усыпляют нить, уступают процессор, возвращают id.

**Параметры:** Как в стандарте.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** Сон — блокировка нити.

**Как работает:** Сон — это ожидание ядра с пределом времени (длительность округляется вверх до миллисекунд); процессор во сне свободен.

**Примечания:** В программах с событиями (клавиши, сообщения, отрисовка) не спите вслепую: ждите событие с пределом ([touch](../native/touch.md), `painter::gui::Area::Wait`) или используйте `box::after` в сопрограммах ([executor](../native/executor.md)).

**Пример:**
```cpp
#include <chrono>
#include <thread>

void Blink()
{
    using namespace std::chrono_literals;
    for (int I = 0; I < 3; I++) std::this_thread::sleep_for(500ms);
}
```

## Синхронизация

### `<mutex>` / `<shared_mutex>` / `<condition_variable>` / `<semaphore>` / `<latch>` / `<barrier>` / `<stop_token>` / `<future>`

**Краткое описание:** Стандартные примитивы синхронизации внутри кабины.

**Параметры:** Как в стандарте.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** Блокировки и пробуждения нитей.

**Как работает:** Все заголовки полные. Мьютексы принадлежат кабине: идентичность владельца `recursive_mutex` — адрес объекта `thread_local`, уникальный для нити в кабине.

**Примечания:** Для разделения памяти между кабинами мьютексы непригодны.

**Пример:**
```cpp
#include <mutex>
#include <thread>
#include <vector>

int Counter()
{
    int Total = 0;
    std::mutex Guard;
    std::vector<std::jthread> Crew;
    for (int I = 0; I < 4; I++)
        Crew.emplace_back([&] { for (int J = 0; J < 1000; J++) { std::scoped_lock Lock(Guard); Total++; } });
    Crew.clear();   // jthread ждёт в деструкторе
    return Total;
}
```

### `<atomic>`

**Краткое описание:** Атомарные операции, включая `wait`/`notify` и 16-байтовые атомики.

**Параметры:** Как в стандарте.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** Нет (кроме ожидания).

**Как работает:** 16-байтовые атомарные операции — через `LOCK CMPXCHG16B` (базовая для всех целевых процессоров); объект должен лежать в записываемой памяти (атомарное чтение 16 байт — это запись тех же байтов). Атомики нестандартного размера — через пул блокировок по адресу. Есть `fetch_max`/`fetch_min` (C++26). `<stdatomic.h>` — псевдонимы `<atomic>`: `_Atomic(T)` означает `std::atomic<T>`.

**Примечания:** Для ожидания на 8-байтовом слове с пределом времени и между кабинами — `box::park` ([strand](../native/strand.md)).

**Пример:**
```cpp
#include <atomic>
#include <thread>

int Handshake()
{
    std::atomic<int> Stage{0};
    std::thread Peer([&] { Stage.wait(0); Stage = 2; Stage.notify_one(); });
    Stage = 1;
    Stage.notify_one();
    Peer.join();
    return Stage.load();
}
```

## Параллельные алгоритмы

### `<execution>` / `std::execution::par`

**Краткое описание:** Параллельные версии алгоритмов работают на бригаде нитей кабины.

**Параметры:** Политики `seq`, `par`, `par_unseq`, `unseq`.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** При первом запросе кабина создаёт **одну** бригаду нитей; между заданиями они спят на ожидании ядра и переиспользуются всеми вызовами.

**Как работает:**
- Одна бригада, одно задание за раз: второй вызов из другой нити ждёт; вложенный параллельный алгоритм выполняется последовательно (стандарт это разрешает).
- Все перегрузки с политикой существуют. Делятся на части: поэлементные (`for_each`, `transform`, `fill`, `copy`…), «по частям и свернуть» (`count`, `reduce`, `transform_reduce`, `min_element`…), «первое совпадение» с досрочной остановкой (`find`, `any_of`, `equal`…), двухпроходные (`copy_if`, `inclusive_scan`…), `sort`/`stable_sort` (сортировка параллельна, слияния — нет).
- Исключение из функции элемента — `std::terminate` (так в стандарте).
- Без нитей бригада пуста, и всё выполняется в вызывающей нити.

**Примечания:** Измерено на 12 ядрах приложений: `transform_reduce` на 400 тыс. элементов — 60 мс → 32 мс.

**Пример:**
```cpp
#include <algorithm>
#include <execution>
#include <numeric>
#include <vector>

double Energy(const std::vector<double> &Samples)
{
    return std::transform_reduce(std::execution::par, Samples.begin(), Samples.end(), 0.0, std::plus<>{},
                                 [](double X) { return X * X; });
}
```
