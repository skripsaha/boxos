# painter::tui::mosaic

## Назначение

Заголовок: [`painter/tui/mosaic.h`](../../../../src/userspace/painter/include/painter/tui/mosaic.h).
Реализация: [`src/tui/mosaic.cpp`](../../../../src/userspace/painter/src/tui/mosaic.cpp).

Ячейка как сетка подпикселей — два по горизонтали и два, три или четыре по
вертикали — и выбор символа с двумя цветами, который лучше всего их
показывает. Это единственное место, где решается, как приблизить ячейку
из нескольких цветов. [FineCanvas](fine_canvas.md) рисует через него;
напрямую модуль нужен, когда программа сама считает цвета подпикселей
(например, уменьшает картинку до ячеек).

## Точные и приближённые сетки

Стекло, которое рисует сетку точно (дисплей сообщает это флагами
`ITEM_MOSAIC_QUADRANTS`, `ITEM_MOSAIC_SEXTANTS`, `ITEM_MOSAIC_OCTANTS`),
показывает любое разбиение подпикселей на два цвета одним символом из
[`boxos_mosaic.h`](../../../../src/include/boxos_mosaic.h):

- квадранты — 2×2 (Rows = 2);
- секстанты — 2×3 (Rows = 3);
- октанты — 2×4 (Rows = 4).

Такую ячейку `ResolveMosaic` подбирает точно — ошибка только в том, что
четыре и более цветов сводятся к двум.

Стекло без точных сеток (текстовая страница VGA, а также framebuffer, если
дисплей их не сообщил) умеет: пробел, верхнюю половину, левую половину, а
на пикселях ещё штриховки. Четвертей нет, поэтому ячейка из четырёх цветов
приближается.

## Типы

### `Mosaic`

**Краткое описание:** Хранит цвета подпикселей одной ячейки.

**Параметры:**
- `Rows` (`std::uint8_t`): строк подпикселей — 2, 3 или 4; по умолчанию 2.
- `At` (`std::array<core::Color, 8>`): цвета в порядке чтения от левого верхнего; подпиксель строки `R` и столбца `C` — `At[R * 2 + C]`.

**Возвращает:** Неприменимо: агрегат.

**Побочные эффекты:** Нет.

**Примечания:** Цвет подпикселя может иметь непрозрачность: `Through()` — ничего не нарисовано, промежуточная — фигура покрывает подпиксель частично.

**Пример:**
```cpp
#include "painter/tui/mosaic.h"

painter::tui::Mosaic Diagonal()
{
    namespace core = painter::core;
    painter::tui::Mosaic Wanted;   // 2×2
    Wanted.At[0] = core::Colors::White; Wanted.At[1] = core::Colors::Black;
    Wanted.At[2] = core::Colors::Black; Wanted.At[3] = core::Colors::White;
    return Wanted;
}
```

### `Mosaic::Count`

**Краткое описание:** Возвращает число подпикселей в ячейке.

**Параметры:** Нет.

**Возвращает:** (`std::size_t`) `Rows * 2`.

**Побочные эффекты:** Нет.

**Пример:**
```cpp
#include "painter/tui/mosaic.h"

void Paint(painter::tui::Mosaic &Wanted, painter::core::Color Ink)
{
    for (std::size_t Place = 0; Place < Wanted.Count(); Place++) Wanted.At[Place] = Ink;
}
```

## Функции

### `MosaicOf`

**Краткое описание:** Возвращает подпиксели, которые показывает существующая ячейка.

**Параметры:**
- `Shown` (`const Cell &`): ячейка.
- `Rows` (`std::uint8_t`): сетка, в которой нужны подпиксели (2, 3 или 4).

**Возвращает:** (`Mosaic`) цвета подпикселей.

**Побочные эффекты:** Нет.

**Как работает:**
- Пробел, блок, половины и любой символ мозаики `boxos_mosaic.h`: каждый подпиксель — цвет символа поверх цвета фона в той доле площади подпикселя, которую закрывает символ (`Color::Over`). Сетка символа может отличаться от `Rows` — доли считаются по перекрытию строк.
- Штриховка: все подпиксели — цвет символа поверх фона в её доле (¼, ½, ¾).
- Любой другой символ (буква, рамка): все подпиксели — цвет фона; штрихи буквы подпиксели передать не могут.

Прозрачные и полупрозрачные цвета ячейки остаются такими в подпикселях.

**Примечания:** Буква под фигурой `FineCanvas` поэтому пропадает: сначала рисуйте фигуры, потом текст.

**Типичное применение:** Прочитать ячейку, изменить часть подпикселей и записать её обратно через `ResolveMosaic`.

**Пример:**
```cpp
#include "painter/tui/mosaic.h"

// Перекрашивает левый верхний подпиксель ячейки.
void Speck(painter::tui::Frame &Out, painter::core::Point At, painter::core::Color Ink)
{
    namespace tui = painter::tui;
    tui::Mosaic Seen = tui::MosaicOf(Out.Read(At), 2);
    Seen.At[0] = Ink;
    (void)Out.Put(At, tui::ResolveMosaic(Seen, Out.Glass(), Out.Mosaics()));
}
```

### `ResolveMosaic`

**Краткое описание:** Возвращает непрозрачную ячейку, картинка которой ближе всего к заданным подпикселям на данном стекле.

**Параметры:**
- `Wanted` (`const Mosaic &`): желаемые подпиксели.
- `Glass` (`GlassKind`): вид стекла.
- `Mosaics` (`std::uint8_t`): флаги `ITEM_MOSAIC_*` — какие сетки стекло рисует точно.

**Возвращает:** (`Cell`) символ с двумя цветами, видимость `Opaque`.

**Побочные эффекты:** Нет.

**Как работает:**
- Все подпиксели одинаковы — пробел этого цвета.
- Пиксельное стекло рисует сетку `Wanted.Rows` точно — перебираются все разбиения подпикселей на «символ» и «фон»; каждое разбиение — символ мозаики, цвет каждой стороны — среднее её подпикселей. Последний подпиксель всегда относится к фону, поэтому разбиение и его дополнение (одна и та же картинка) считаются один раз. Выбирается разбиение с наименьшей ошибкой; при равенстве побеждает один цвет.
- Иначе сетка сначала сводится к двум строкам (средним света подпикселей по площади перекрытия), и кандидаты такие: верхняя половина ▀, левая половина ▌, один цвет, а на пиксельном стекле ещё штриховки — ▒ как диагональ двух цветов, ░ и ▓ как «пыль»: один подпиксель против трёх. Штриховка — текстура, поэтому её ошибка увеличивается тем сильнее, чем дальше друг от друга её цвета, и она выбирается только там, где разбиение не может передать ячейку так же хорошо.

Цвета смешиваются как свет (через таблицы `BoxColorLight`/`BoxColorCode`), а ошибка — это квадрат разности цветов с весами 2:4:3 для красного, зелёного и синего (глаз сильнее различает зелёный).

**Примечания:**
- На текстовой странице штриховок нет (16 цветов превращают дизеринг в шум), а цвет стороны — не среднее, а тот цвет из её подпикселей, который ближе всего к среднему: смесей там нет.
- Подпиксели с непрозрачностью учитываются в ошибке наравне с цветом. Цвет стороны — среднее света, взвешенное непрозрачностью, при средней непрозрачности; сторона, где ничего не видно, становится `Through()`. Ячейка с такими подпикселями никогда не будет штриховкой (та закрасила бы всё) — только разбиение или один цвет. Неполную непрозрачность дисплей смешивает с тем, что под ячейкой.

**Типичное применение:** Уменьшение картинки до ячеек; собственные фигуры, которых нет в `FineCanvas`.

**Пример:**
```cpp
#include "painter/tui/mosaic.h"

// Кладёт в ячейку картинку из четырёх цветов 2×2.
bool Tile(painter::tui::Frame &Out, painter::core::Point At, const std::array<painter::core::Color, 4> &Four)
{
    painter::tui::Mosaic Wanted;
    for (std::size_t Place = 0; Place < 4; Place++) Wanted.At[Place] = Four[Place];
    return Out.Put(At, painter::tui::ResolveMosaic(Wanted, Out.Glass(), Out.Mosaics()));
}
```
