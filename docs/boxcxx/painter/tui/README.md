# painter::tui — текстовая графика и псевдографика

## Назначение

`painter::tui` — подсемейство Painter для интерфейсов из текстовых ячеек:
надписей, рамок, полноэкранных программ, временных фигур поверх консоли и
рисунков, остающихся частью вывода. Оно предоставляет кадр в памяти,
публикацию слоёв, ввод клавиш и операции рисования средствами шрифта BoxOS.

Программа задаёт изображение и читает типизированные события. Обмен общей
памятью, Touch-подписка и сообщения DisplayServer скрыты внутри библиотеки.
Модель программы, правила игры, анимационное время, настройки, хранение в
TagFS и разбор команд остаются ответственностью приложения.

TUI работает и на текстовой странице, и при framebuffer-выводе. В обоих
случаях результат состоит из глифов. `GlassKind::Pixels` сообщает тип
устройства вывода, а не включает API физических пикселей. Настоящий
пиксельный GUI отнесён к `painter::gui`, реализации которого в текущем
дереве нет. Общие координаты и цвета принадлежат `painter::core`.

## Выбор поверхности

| Задача | Интерфейс | Ввод | После закрытия |
| --- | --- | --- | --- |
| Полноэкранная программа со своим кадром | `Stage` | Встроенный `Keyboard` | Слой удаляется |
| Временная фигура или панель поверх сцены | `Surface` | Отдельный `Keyboard`, если нужен | Слой удаляется |
| Рисунок, который должен остаться в выводе | `ConsoleSurface` | Отдельный `Keyboard`, если нужен | После успешного `Commit` рисунок остаётся в тексте |

Размеры в `Open` — минимально допустимая ширина и высота всей консоли.
Возвращённый объект использует фактический размер консоли. Для маленькой
фигуры создайте отдельный `Frame` нужного размера и скопируйте его область
в поверхность. У `Surface` нет публичного `Paint`; он предоставляет
`Composite`. `ConsoleSurface::Paint` принудительно делает покрытие ячеек
непрозрачным.

## Ячейки, координаты и цвет

Обычная координата `{X, Y}` означает столбец и строку от левого верхнего
угла. Прямоугольники используют начало и размеры, а не правую и нижнюю
координаты. Область шириной W охватывает X от начала до начала + W
исключительно.

`Frame::PutPixel` использует одну точку по ширине ячейки и две по высоте.
`FineCanvas` использует те же геометрические единицы, оценивая две
подъячейки по ширине и две по высоте. Итог всё равно занимает одну ячейку
с одним глифом и двумя цветами; произвольные четыре цвета приближаются.

`Cell::Glyph` — символ Unicode, а не номер глифа: какой глиф его рисует,
решает дисплей. Символ кладут в ячейку `Put` и `Fill`; текст UTF-8 принимают
`Write`, `Centre` и `PutText`. Ширина текста считается в ячейках и
измеряется `CellsOf`; число байтов строки не равно экранной ширине.
Поддержка символов ограничена шрифтами дисплея: корректная
кодировка UTF-8 сама по себе не гарантирует наличие глифа.

Цвет `core::Color` хранит RGB или специальное значение. `Screen()` означает
цвет экрана по назначению поля; `Through()` — нижнее содержимое в этой
позиции. `WithOpacity` задаёт непрозрачность, квантованную в 63 шага на
проводе. На текстовой странице конечные RGB преобразуются в аппаратную
палитру при выводе. Не определяйте тип устройства по размеру экрана:
запрашивайте `Glass()`.

Для FineCanvas на самостоятельно созданном Frame вызовите
`Frame::SetGlass(Surface::Glass())` или соответствующий метод другой
поверхности. Stage назначает режим собственному кадру сам.

## Рисование и публикация

Клеточные операции Frame изменяют только память. `Stage::Present`,
`Surface::Composite` и `ConsoleSurface::Paint` публикуют результат отдельно.
Запись в Frame отсекается его границами; копирование Region в поверхность
требует полного вхождения источника и назначения и возвращает ошибку вместо
отсечения.

`Frame::Clear` создаёт непрозрачный фон, `ClearTransparent` — прозрачный.
При `Surface::Composite` прозрачные ячейки удаляют прежнее покрытие внутри
заменяемой области слоя. Старая область фигуры не очищается автоматически
при перемещении в другую позицию. Для полной замены слоя используйте
`Surface::Clear()` и следующий `Composite`: Clear очищает локальный буфер
без отправки отдельного пустого кадра.

Каретка кадра хранится отдельно от ячеек и отсутствует до SetCaret.
`CellMark` — дополнительная отметка конкретной ячейки. Перенос прямоугольника
также переносит каретку внутри него. `ConsoleSurface` отдельно хранит
позицию продолжения консоли; подробности взаимодействия с прокруткой
описаны на его странице.

Сервер может пропустить ещё не прочитанный промежуточный кадр анимации в
пользу нового. Успешная публикация не означает подтверждение физического
показа каждого кадра. Ошибка транспорта не всегда означает отсутствие
эффекта: локальный буфер или слот могли быть изменены до её возврата.

## Полноэкранная программа

Пример открывает сцену, выводит надпись и ждёт Escape, завершения ввода
или запроса завершения. Он проверяет публикацию и явное закрытие.

```cpp
#include "painter/tui/stage.h"
#include "painter/tui/text.h"

int main()
{
    namespace tui = painter::tui;
    namespace core = painter::core;

    auto Screen = tui::Stage::Open(20, 4);
    if (!Screen) return 1;
    Screen->HearEnd();

    tui::Frame &Out = Screen->FrameBuffer();
    Out.Clear();
    tui::PutText(Out, {1, 1}, "Painter", Out.Size().Width - 2,
                 core::Colors::White, core::Colors::Black);
    if (!Screen->Present()) return 2;

    int Result = 0;
    for (;;) {
        const auto Event = Screen->Wait();
        if (Event.Kind == tui::EventKind::Gone) {
            if (Event.Cause) Result = 3;
            break;
        }
        if (Event.Kind == tui::EventKind::EndAsked) break;
        if (Event.Kind == tui::EventKind::Key &&
            Event.Key.Character == tui::KeyCodes::Escape) break;
    }
    if (!Screen->Close()) return 4;
    return Result;
}
```

## Временная фигура

Отдельный Frame позволяет рисовать маленький объект на поверхности полного
размера. Фигура остаётся до нажатия клавиши или окончания ввода.

```cpp
#include "painter/tui/fine_canvas.h"
#include "painter/tui/keyboard.h"
#include "painter/tui/surface.h"

int main()
{
    namespace tui = painter::tui;
    namespace core = painter::core;

    auto Screen = tui::Surface::Open(20, 8);
    if (!Screen) return 1;
    auto Picture = tui::Frame::Create({12, 6});
    if (!Picture) return 2;
    Picture->SetGlass(Screen->Glass());
    Picture->ClearTransparent();
    tui::FineCanvas Fine(*Picture);
    Fine.Disc(6, 6, 4, core::Colors::Cyan);

    auto Ear = tui::Keyboard::Open();
    if (!Ear) return 3;
    if (!Screen->Composite({2, 1}, *Picture)) return 4;
    int Result = 0;
    for (;;) {
        const auto Event = Ear->Wait();
        if (Event.Kind == tui::EventKind::Key) break;
        if (Event.Kind == tui::EventKind::Gone) {
            if (Event.Cause) Result = 5;
            break;
        }
    }
    if (!Ear->Close()) Result = 6;
    if (!Screen->Close()) Result = 7;
    return Result;
}
```

## Рисунок в выводе консоли

Пример публикует надпись в верхней строке, устанавливает место продолжения
в следующей строке и фиксирует результат. После успеха Commit временный
слой уже закрыт. При раннем выходе деструктор отменяет незавершённый слой.

```cpp
#include "painter/tui/console_surface.h"
#include "painter/tui/text.h"

int main()
{
    namespace tui = painter::tui;
    namespace core = painter::core;

    auto Screen = tui::ConsoleSurface::Open(20, 3);
    if (!Screen) return 1;
    auto Picture = tui::Frame::Create({12, 1});
    if (!Picture) return 2;
    Picture->Clear();
    tui::PutText(*Picture, {0, 0}, "Painter", 12,
                 core::Colors::White, core::Colors::Black);
    if (!Screen->Paint({0, 0}, *Picture)) return 3;
    if (!Screen->SetCursor({0, 1})) return 4;
    if (!Screen->Commit()) return 5;
    return 0;
}
```

## Владение и ошибки

Stage, Surface, ConsoleSurface и Keyboard нельзя копировать; их можно
перемещать. Деструкторы освобождают ресурсы и не возвращают ошибки
закрытия. Когда статус важен, вызывайте Close явно. Frame также перемещаемый
и некопируемый; FineCanvas только ссылается на него.

Фабрики поверхностей возвращают `std::expected<..., StageError>`;
операции публикации — `box::status`. `Frame::Create` возвращает
`box::result<Frame>`. Для диагностики открытия доступны Kind, Cause,
Actual, Required и `StageError::Describe`. Текстовые функции, создающие
строки, могут передавать исключения; подробности приведены у каждой функции.

Операции одного изменяемого кадра или объекта поверхности не защищены
общей блокировкой. При использовании из нескольких потоков синхронизацию
обеспечивает программа. Атомарный протокол общей памяти с DisplayServer
не заменяет такую синхронизацию.

## Исходники и сборка

Библиотека находится в [src/userspace/painter](../../../../src/userspace/painter/README.md).
Публичные заголовки лежат в `include/painter/tui`, реализации — в `src/tui`.
Все модули входят в `libpainter.a`. Для C++ используется C++23 и среда BoxOS:
заголовки boxcxx, boxlib и общие заголовки системы.

[Makefile Painter](../../../../src/userspace/painter/Makefile) задаёт
состав архива и параметры компиляции;
[Makefile утилит](../../../../src/userspace/utils/Makefile) показывает
связку startup, программы, `libpainter.a`, `libboxcxx.a`, `libbox.a` и libgcc.
Это статическая библиотека BoxOS, а не библиотека терминала хостовой ОС.

Для полной сборки и запуска проекта используется `make clean && make && make run`.
Примеры на страницах модулей — самостоятельные единицы трансляции; функции
с параметром поверхности предполагают уже открытый объект. Три примера
этой страницы содержат полный `main`.

API и детали внутреннего протокола разделены страницами модулей.
