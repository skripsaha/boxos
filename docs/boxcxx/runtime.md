# Рантайм boxcxx

## Назначение

Исходники: [`src/userspace/boxcxx/src`](../../src/userspace/boxcxx/src) — `runtime/`, `unwind/`, `tls/`;
стартовый код — [`boxlib_start.asm`](../../src/userspace/boxlib/boxlib_start.asm).

boxcxx — собственная реализация стандартной библиотеки C++ и рантайма
Itanium C++ ABI для BoxOS: не порт libstdc++ или libc++. Всё, что
компилятор ждёт от рантайма, сделано здесь: запуск и завершение программы,
статические конструкторы и деструкторы, исключения и раскрутка стека,
RTTI и `dynamic_cast`, операторы `new`/`delete`, `thread_local`.

Эта страница — о том, как это ведёт себя в BoxOS. Стандартная семантика
не пересказывается.

## Сборка программы

Программа на C++ компилируется кросс-компилятором с флагами boxcxx и
линкуется в таком порядке: стартовый код `boxlib_start.o`, объекты
программы, (`libpainter.a`, `libtypecase.a` при необходимости),
`libboxcxx.a`, `libbox.a`, `-lgcc`. `libboxcxx.a` стоит **до** `libbox.a`:
часть функций C (`printf`, `getchar`) объявлена в boxlib слабыми, и
программа на C++ получает полные версии из boxcxx.

Флаги компиляции (как в `src/userspace/utils/Makefile`):

```make
CXXFLAGS = -std=gnu++23 -nostdinc++ -fexceptions -frtti -fcoroutines -fuse-cxa-atexit \
           -fasynchronous-unwind-tables -nostdlib -ffreestanding -fno-builtin -mno-red-zone \
           -fno-stack-protector -fpie -static -fno-ipa-ra -fcf-protection=full \
           -fstack-clash-protection -fno-delete-null-pointer-checks -fno-strict-aliasing -fwrapv \
           -I../boxcxx/include/std -I../boxcxx/include -I../boxlib/include -I../../include
```

Исключения, RTTI и сопрограммы включены. Пошаговое подключение новой
программы — [первая программа](first-program.md).

## Запуск и завершение

### `_start` → `main`

**Краткое описание:** Готовит процесс и вызывает `main`.

**Параметры:** `main` вызывается с `argc = 0` и `argv = nullptr`.

**Возвращает:** Код возврата `main` уходит в `exit()`.

**Побочные эффекты:** Выравнивает стек, запускает глобальные конструкторы (в порядке приоритетов), вызывает `main`.

**Как работает:** Слова командной строки программа не получает через `argv`: то, что сказал запустивший, лежит в кабине как Luggage ([luggage](native/luggage.md)), а поля, разложенные оболочкой, — в Form ([form](form.md)). TLS главной нити ядро создаёт заранее (приоритет конструктора 101); стандартные потоки `std::cout`/`std::cin` создаются конструктором с приоритетом 102 — раньше любого глобального конструктора программы, поэтому в глобальном конструкторе можно писать в `std::cout`.

**Примечания:** Стартовый код несёт `ENDBR64` для CET.

**Пример:**
```cpp
#include "box/cxx/luggage.h"

int main()
{
    return box::luggage::size() > 1 ? 0 : 1;   // есть ли слова после имени программы
}
```

### `exit` / `quick_exit` / `abort` / `std::terminate`

**Краткое описание:** Завершают процесс разными путями.

**Параметры:** Код выхода (`int`) для `exit`/`quick_exit`.

**Возвращает:** Не возвращают.

**Побочные эффекты:**
- `exit` (и возврат из `main`) — деструкторы `thread_local` главной нити, функции `atexit` и статические деструкторы в обратном порядке (`__cxa_finalize`), сброс потоков.
- `quick_exit` — только функции `at_quick_exit` (свой список, растёт по требованию).
- `abort` — сразу, без `atexit` и статических деструкторов; код выхода 128 + `SIGABRT`.
- `std::terminate` (неперехваченное исключение, вызов чистой виртуальной функции, неудача `new` без обработчика) — диагностика и `abort`.

**Примечания:** Главная нить заканчивается только возвратом из `main`; `box::this_strand::exit()` в главной нити — `std::terminate`. Принудительно убитый процесс ([child](native/child.md) `kill`) деструкторов не выполняет.

**Пример:**
```cpp
#include <cstdlib>
#include <print>

void Bye() { std::println("до свидания"); }

int main()
{
    std::atexit(Bye);
    return 0;
}
```

## Исключения

### Бросок и перехват

**Краткое описание:** Полная поддержка исключений C++ по Itanium ABI.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Бросок выделяет объект исключения из кучи; при нехватке памяти — из аварийного пула (общий, захватывается атомарно).

**Как работает:** Двухфазная раскрутка ([abi.eh] §1.3): фаза поиска вызывает функцию личности каждого кадра (`__gxx_personality_v0`, разбирает `.gcc_except_table`), фаза очистки выполняет деструкторы и передаёт управление обработчику. Кадры описывает DWARF CFI, его разбирает собственный движок boxcxx (`unwind/dwarf_cfi.cpp`). Состояние исключений (стек перехваченных, счётчик неперехваченных) своё у каждой нити. При раскрутке учитывается теневой стек CET.

**Примечания:** Исключение, вылетевшее из функции нити или из параллельного алгоритма, — `std::terminate`, как требует стандарт.

**Пример:**
```cpp
#include <print>
#include <stdexcept>

int Parse(int Value)
{
    if (Value < 0) throw std::invalid_argument("отрицательное");
    return Value;
}

int main()
{
    try {
        return Parse(-1);
    } catch (const std::exception &Problem) {
        std::println("ошибка: {}", Problem.what());
        return 1;
    }
}
```

### Ошибки BoxOS без исключений

**Краткое описание:** Операции BoxOS сообщают о неудаче значением, а не исключением.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Нет.

**Как работает:** Функции `box::` возвращают `box::result<T>` / `box::status` с настоящей причиной из ядра ([error](native/error.md)). Исключения остаются для стандартной библиотеки (`std::bad_alloc`, `std::out_of_range`…) и для ошибок программы. errno не существует: `<cerrno>` есть ради кода C, но ни boxlib, ни `box::` его никогда не устанавливают.

**Пример:** См. [error](native/error.md).

## RTTI

### `typeid` / `dynamic_cast` / `std::type_info`

**Краткое описание:** Полная информация о типах во время выполнения.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Нет.

**Как работает:** `type_info` сравнивается по указателю на декорированное имя; разные типы имеют разные имена, поэтому `==` и `before` всегда согласованы и задают строгий порядок (`std::type_index` в контейнерах работает). `dynamic_cast` реализован в рантайме (`runtime/dynamic_cast.cpp`). Есть `__cxa_demangle` (`<cxxabi.h>`, в `__cxxabiv1` и в глобальном пространстве имён; привычного по libstdc++ псевдонима `abi::` нет): около 93 % имён совпадает с libiberty байт в байт; при отказе возвращается `nullptr`, и вызывающий печатает декорированное имя.

**Пример:**
```cpp
#include <cstdlib>
#include <cxxabi.h>
#include <print>
#include <typeinfo>
#include <vector>

void Name()
{
    int Status = 0;
    char *Pretty = __cxa_demangle(typeid(std::vector<int>).name(), nullptr, nullptr, &Status);
    std::println("{}", Pretty ? Pretty : typeid(std::vector<int>).name());
    std::free(Pretty);
}
```

## Память

### `operator new` / `operator delete`

**Краткое описание:** Полный набор заменяемых функций выделения поверх кучи boxlib.

**Параметры:** Как в стандарте, включая выравнивающие и `nothrow` формы.

**Возвращает:** Как в стандарте.

**Побочные эффекты:** Вызывают `malloc`/`free` boxlib (потокобезопасны).

**Как работает:** При нехватке памяти вызывается `std::new_handler`, если он установлен; без него обычный `new` бросает `std::bad_alloc`, `nothrow`-форма возвращает `nullptr`. Выравнивающие формы выделяют с запасом и хранят исходный указатель перед выровненным адресом. `aligned_alloc` реализован внутри распределителя, поэтому его результат освобождается обычным `free`.

**Примечания:** Для учёта памяти по подсистемам и выделения без исключений с настоящей причиной — [heap](native/heap.md). Комментарий в `new_delete.cpp` («throwing forms terminate») устарел: код бросает `std::bad_alloc`.

**Пример:**
```cpp
#include <new>
#include <print>

void Low() { std::println("память кончилась"); std::set_new_handler(nullptr); }

int main()
{
    std::set_new_handler(Low);
    int *Many = new (std::nothrow) int[1000];
    delete[] Many;
    return 0;
}
```

## Статические и локальные для нити объекты

### Статические объекты и `static` в функциях

**Краткое описание:** Инициализируются и уничтожаются по правилам C++.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Деструкторы — при `exit` в обратном порядке.

**Как работает:** Реестр статических деструкторов (`__cxa_atexit`) общий для процесса. Инициализация локальной `static` защищена атомарным флагом: если две нити впервые входят одновременно, инициализатор выполнится ровно один раз.

**Пример:**
```cpp
#include <string>

const std::string &Greeting()
{
    static const std::string Text = "привет";   // один раз, даже из нескольких нитей
    return Text;
}
```

### `thread_local`

**Краткое описание:** Объекты, свои у каждой нити.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Деструкторы выполняются при завершении нити.

**Как работает:** Ядро создаёт TLS нити из шаблона программы до её первой инструкции, поэтому начальные значения готовы сразу. Реестр деструкторов `thread_local` свой у каждой нити и без блокировок; `std::thread`, `box::strand` и `box::spawn_detached` выполняют его при окончании нити, сырой нити — вручную ([tls_strand](native/tls_strand.md)).

**Пример:**
```cpp
#include <atomic>
#include <thread>

thread_local int Calls = 0;

int Count()
{
    std::atomic<int> Total{0};
    std::thread A([&] { Calls++; Total += Calls; });
    std::thread B([&] { Calls++; Total += Calls; });
    A.join();
    B.join();
    return Total.load();   // 2: у каждой нити свой Calls
}
```

## Сопрограммы

### `co_await` / `co_return` / `std::generator`

**Краткое описание:** Сопрограммы C++20 работают; для ожидания событий BoxOS есть свой цикл.

**Параметры:** Нет.

**Возвращает:** Неприменимо.

**Побочные эффекты:** Кадры сопрограмм выделяются в куче.

**Как работает:** `<coroutine>` и `<generator>` стандартные. Ожидание событий системы (Touch, сообщения, Brook, таймеры, файловый ввод-вывод, окончание нитей) — `box::task<T>` и `box::executor` ([executor](native/executor.md)).

**Пример:**
```cpp
#include <generator>

std::generator<int> Squares(int Count)
{
    for (int I = 1; I <= Count; I++) co_yield I * I;
}
```
