# Form — входные данные и результат программы

## Назначение

Form — декларация того, что программа принимает и что возвращает.
Она хранится в самой программе и доступна оболочке до её запуска.
Оболочка сопоставляет слова команды с полями, разрешает имена файлов,
при необходимости задаёт вопросы и передаёт готовые значения программе.

Например, программа объявляет «принимаю файлы и слова», а получает
идентификаторы файлов и список строк. Ей не требуется самостоятельно
реализовывать выбор между одноимёнными файлами, разбор `it` и `them`
или подтверждение выбора всего тома.

Form определяет форму результата; [Souvenir](souvenir.md) передаёт
вызывающей стороне идентификаторы файлов результата. Декларация
`gives things` сама по себе ничего не отправляет.

Руководство описывает поведение текущих `box/form.h`,
`box/cxx/form.h`, реализации `form*.c` и оболочки `hub`.
Примеры C++ собираются с BoxCxx, как в
[руководстве первой программы](first-program.md).

## Декларация и заполненные значения

Это два разных представления с разными сроками жизни:

| Представление | Где находится | Что содержит |
|---|---|---|
| Декларация Form | Часть `form` в `.box`, секция `.boxos.form` в ELF | Виды и порядок полей, обязательность, описания и вид результата. |
| Заполненная Form | Записи в Luggage конкретного запуска | Идентификаторы выбранных файлов и переданные строки. |

Одна декларация используется при многих запусках с разными значениями.
Назначение полей задаёт программа; их значения определяются командой
и решениями человека при запуске.

В `.box` штатный упаковщик помечает `form` как `LOAD_AT_START`.
Программа читает её из собственной памяти через таблицу загруженных
частей. Запускающая сторона читает ту же декларацию из файла через
`form_of_file()`. Раскладка контейнера описана в
[спецификации .box](../box-format.md).

## Объявление в C++

Подключите `box/cxx/form.h`, если нужны интерфейсы C++; он также
подключает `box/form.h` с макросом `BOX_FORM`.

```cpp
#include "box/cxx/form.h"

BOX_FORM("takes things Files \"the files to inspect\"\n"
         "takes optional words Labels \"the labels to use\"\n"
         "gives things\n");
```

В этом примере поле `0` содержит файлы, поле `1` — слова.
Имена `Files` и `Labels` не меняют числовую адресацию интерфейса C++.
Они позволяют ссылаться на поля в Itinerary и используются при
представлении декларации.

### `BOX_FORM`

**Краткое описание:** Объявите входные поля и вид результата программы.

**Параметры:**

- `Text` (строковый литерал): строки декларации без заголовка `form` (его добавляет макрос).

**Возвращает:** Неприменимо: макрос создаёт статический массив `BoxFormDeclared`.

**Побочные эффекты:** Добавляет неизменяемые байты в секцию `.boxos.form` исполняемого образа.

**Как работает:** Макрос добавляет `form\n`, помещает результат в отдельную секцию и помечает его `used`. При упаковке в `.box` конечные NUL секции удаляются, а текст становится частью `form`. Макрос не выполняет синтаксическую проверку строк декларации.

**Примечания:** Размещайте одну декларацию на программу на уровне файла, вне функций. Для программы без полей используйте `BOX_FORM("")`; выражение `takes no words` не является объявлением пустой Form. Успешная компиляция литерала и успешная упаковка не заменяют предметный разбор `takes` и `gives`.

**Типичное применение:** Объявляйте Form рядом с подключениями основного исходника, затем читайте значения через `box::form`.

**Пример:**

```cpp
#include "box/cxx/form.h"

BOX_FORM("");

int main() { return 0; }
```

## Язык декларации

Текстовая декларация начинается строкой `form` (номера версии нет: заголовок с чем-либо после `form` отвергается). Каждая следующая строка
описывает поле или результат:

```text
form
takes [optional] KIND [NAME] "описание"
gives things
```

Квадратные скобки здесь обозначают необязательные элементы синтаксиса
и не записываются в декларацию.

| KIND | Значение | Интерфейс C++ |
|---|---|---|
| `thing` | Один файл. | `box::form::things()`. |
| `things` | Один или несколько файлов. | `box::form::things()`. |
| `name` | Одно слово имени, в том числе ещё не существующего файла. | `words()` или `text()`. |
| `words` | Список слов. | `words()` или `text()`. |
| `text` | Остаток текстовой команды. | `text()`; `words()` представляет его одной строкой. |
| `into` | Имя назначения после `->`. | `text()` или `words()`. |

`optional` разрешает пустое поле. Без него незаполненное поле вызывает
вопрос оболочки; при запуске без возможности задать вопрос заполнение
отказывает. Максимум — `BOX_FORM_FIELDS = 16` полей.

Необязательное `NAME` начинается с латинской буквы, затем допускает
латинские буквы, цифры и `_`. Имена уникальны среди полей и не могут
быть `them`, `it`, `all`, `everywhere`. Это имя поля, а не значение,
которое человек обязан писать перед аргументом команды.

Описание в двойных кавычках используется при вопросе о недостающем поле.
Текущий парсер допускает отсутствие описания, но тогда вопрос теряет
пояснение. После закрывающей кавычки не должно быть лишних слов.

Результат объявляется строкой `gives things` или `gives text`.
Если строки нет, `Gives` имеет значение `BOX_FORM_GIVES_NOTHING`.
Для файлового результата вызывайте Souvenir; для текстового — пишите
обычным интерфейсом вывода.

Неизвестные виды строк декларации пропускаются для расширения языка.
Однако неизвестный `KIND` после `takes` отвергается: пропуск такого поля
изменил бы смысл всех следующих индексов. Не используйте это свойство
как проверку опечаток: неизвестная строка может быть просто пропущена.

Для `.box` используйте LF, без TAB, CR и внутренних NUL: это правила
текстовой части контейнера. Сам C-парсер исторически принимает некоторые
другие пробельные байты, но упаковщик проверяет более строгую оболочку.
`form_of_file()` ограничивает читаемую Form 65536 байтами.

## Как слова становятся полями

Заполнитель проходит поля в порядке декларации. Это не обычное
позиционное разложение слов по номерам аргументов:

- `thing` и `things` выбирают слова, обозначающие файлы; идентификаторы
  сохраняются в порядке выбора без повторов внутри одного поля;
- `words` забирает доступные обычные слова, не занятые файловыми полями;
- `name` сначала ищет одно обычное слово, а при его отсутствии может
  использовать имя файла, не взятое другим полем;
- `text` получает остаток строки начиная с первого ещё не занятого
  элемента; внутренние пробелы и кавычки сохраняются в текстовом представлении;
- `into` получает имя назначения стрелки;
- неиспользованное слово в объявленной Form вызывает отказ;
- недостающее обязательное значение вызывает вопрос.

Если в Form нет `thing` и `things`, поиск файлов для обычных слов
не выполняется. Поэтому слово, совпадающее с именем существующего файла,
не должно неожиданно исчезать из текстовой команды. Если первым полем
является `text`, оно забирает текст до последующих файловых полей.
Порядок декларации влияет на результат: размещайте поля осознанно.

Для такого контракта:

```text
takes things "the files to tag"
takes words "the tags to add"
```

команды `tag a.txt urgent` и `tag urgent a.txt` могут дать одинаковые
значения: файл `a.txt` и слово `urgent`, если последнее не обозначает файл.
Окончательная интерпретация зависит от содержимого тома и Use Context,
а не только от порядка токенов.

### Кавычки, запятые и специальные слова

Двойные кавычки объединяют слова; запятая вне кавычек связывает элементы
списка. `a.txt,b.txt`, `a.txt, b.txt` и `a.txt ,b.txt` обозначают один
список. Если список содержит файл и элемент, который не удалось найти
как файл, заполнитель не превращает этот элемент молча в отдельную метку.

| Слово | Значение при наличии файловых полей |
|---|---|
| `them` | Все файлы последнего сохранённого результата оболочки. |
| `it` | Один файл этого результата; если их несколько, нужно выбрать. |
| `all` | Все перечисляемые файлы текущего Use Context. |
| `everywhere` | Расширить поиск последующих имён и `all` на весь том. |

В кавычках эти слова теряют специальную роль. Это не отключает
разрешение обычного имени там, где поле ожидает файл: `"it"` может
обозначать настоящий файл с таким именем. В чисто текстовой Form
`them`, `it`, `all`, `everywhere` являются обычными словами.

Для прямого поиска имени исключаются файлы с `trashed`; `hidden` сам
по себе не запрещает обращение по имени. Перечисление `all` исключает
и `trashed`, и `hidden`. Поиск вне контекста не отменяет эти правила.
Если `all` охватывает весь том, заполнитель просит подтверждение.

Имена полей текущего Itinerary также могут подставлять переданные ему
файлы или слова. Именованный список файлов передаётся как `them`, список
слов — в словесные поля, а в `text` его слова соединяются пробелами.
В кавычках имя остаётся буквальным.

## Запуск через оболочку

Последовательность в `hub/fill.cpp`:

1. Прочитать Form выбранной программы.
2. Передать заполняющему механизму строку после имени команды, поиск
   по тому, текущие `it`/`them` и поля Itinerary.
3. Ответить на запросы выбора файла, недостающего поля или подтверждения.
4. При необходимости создать файл для текстовой стрелки.
5. Записать заполненные значения в Luggage.
6. Запросить Souvenir, если `gives things` и стрелка не сделала экран файлом.
7. Добавить признак `here`, если программа запускается перед человеком.
8. Запустить программу с этими байтами.

Неоднозначное имя приводит к выбору, а не к использованию случайного
совпадения. Отказ или отмена вопроса не должны запускать программу
с частично заполненными значениями.

## Запуск другим способом

Если вызывающая программа уже передала корректные записи `filled 1`,
BoxLib проверяет их по собственной Form получателя. Если передана только
строка, BoxLib при первом обращении к полям пытается заполнить Form сама
тем же механизмом, используя том и Use Context.

В этом режиме никто не отвечает на вопросы. Неоднозначный файл,
незаполненное обязательное поле или неподтверждённый `all` всего тома
приводят к отказу. BoxLib один раз объясняет причину на экране; доступ
через `box::form` возвращает `invalid_argument`. Получив ошибку,
программа должна завершить выбранную операцию сама: чтение Form не
вызывает автоматический `exit()`.

Поля подготавливаются один раз на Cabin. Первое обращение выполняет
инициализацию, остальные Strand ждут публикации результата. Готовые
представления доступны до конца жизни процесса и не принадлежат вызывающему.

При самостоятельном заполнении BoxLib не получает историю `them`
оболочки и не просит Souvenir от её имени. Перенаправление экрана через
`->` без поля `into` требует участия оболочки и в этом режиме отвергается.

## Чтение в C++

### `box::form::things`

**Краткое описание:** Получите идентификаторы файлов заполненного поля.

**Параметры:**

- `field` (`std::uint32_t`, in): индекс поля, начиная с нуля.

**Возвращает:** `box::result<std::span<const file_id_t>>`: заимствованное представление либо ошибка.

**Побочные эффекты:** При первом обращении подготавливает и сохраняет заполненную Form; может выделять память, читать метаданные тома и выводить причину отказа.

**Как работает:** Вызывает `form_things()`, который требует поле вида `thing` или `things`. C++-обёртка превращает отрицательный код в `box::error`, а успешную пару указателя и количества — в `std::span`.

**Примечания:** Для пустого необязательного поля возвращается успешный пустой диапазон. Неверный индекс, неверный вид поля или отказ подготовки дают `invalid_argument`. Идентификаторы не означают владения файлами и не фиксируют их состояние во времени; читать содержимое и проверять ошибки нужно отдельными операциями TagFS.

**Типичное применение:** Получите диапазон один раз, проверьте результат, затем обрабатывайте файлы по идентификаторам.

**Пример:**

```cpp
#include "box/cxx/form.h"

box::result<std::size_t> FileCount()
{
    auto Files = box::form::things(0);
    if (!Files) return std::unexpected(Files.error());
    return Files->size();
}
```

### `box::form::words`

**Краткое описание:** Получите строки словесного поля.

**Параметры:**

- `field` (`std::uint32_t`, in): индекс поля, начиная с нуля.

**Возвращает:** `box::result<std::span<const char *const>>`: диапазон указателей на NUL-завершённые строки либо ошибка.

**Побочные эффекты:** При первом обращении подготавливает Form так же, как `things()`.

**Как работает:** Вызывает `form_words()` для `words`, `name`, `text` или `into`. `name`, `text` и `into` представлены не более чем одной строкой; `words` может содержать несколько. Обёртка не копирует строки.

**Примечания:** `thing` и `things` для этого метода недопустимы. Строки и сам диапазон нельзя освобождать или изменять. Необязательное пустое поле даёт пустой диапазон.

**Типичное применение:** Используйте `words()` для отдельных меток, а `text()` — когда требуется одна строка.

**Пример:**

```cpp
#include "box/cxx/form.h"

box::result<bool> HasWords(std::uint32_t Field)
{
    auto Words = box::form::words(Field);
    if (!Words) return std::unexpected(Words.error());
    return !Words->empty();
}
```

### `box::form::text`

**Краткое описание:** Получите словесное поле одной строкой.

**Параметры:**

- `field` (`std::uint32_t`, in): индекс поля, начиная с нуля.

**Возвращает:** `box::result<std::string_view>`: заимствованная строка либо `invalid_argument`.

**Побочные эффекты:** Первичная подготовка Form создаёт сохранённую строку для каждого словесного поля.

**Как работает:** `form_text()` возвращает результат соединения значений поля одиночными пробелами. Для `words` это соединение нескольких слов; для `text` само значение уже содержит остаток исходной строки, поэтому внутренние пробелы и кавычки не нормализуются этим соединением.

**Примечания:** Пустое необязательное поле даёт успешную пустую строку. Файловое поле и неверный индекс дают ошибку. При отказе подготовки C++-обёртка получает только отсутствие строки и возвращает `invalid_argument`, без отдельного исходного кода выделения памяти или поиска.

**Типичное применение:** Читайте `text`, `name` и `into`, когда список отдельных строк не нужен.

**Пример:**

```cpp
#include "box/cxx/form.h"

box::result<std::string_view> Destination()
{
    return box::form::text(1);
}
```

## Полный пример текстовой команды

Пример выводит переданный текст. Название исходника и добавление в сборку
выберите по [руководству первой программы](first-program.md).

```cpp
#include <print>

#include "box/cxx/form.h"
#include "box/print.h"

BOX_FORM("takes text \"the text to print\"\n"
         "gives text\n");

int main()
{
    auto Text = box::form::text(0);
    if (!Text) {
        print_to_screen("Cannot read the text field.\n");
        return 1;
    }
    std::println("{}", *Text);
    return 0;
}
```

Для учебного имени `echoform` команда `echoform hello   world` передаёт
текст с внутренними пробелами. `echoform hello -> note.txt` передаёт
полю текст `hello`, а вывод собирается в файл `note.txt`.

Пример не читает клавиатуру, не ищет файлы и не создаёт Souvenir:
его результат — обычный текстовый вывод.

## Стрелка и присутствие человека

`->` обрабатывается до передачи строки программе и удаляется из её
обычной части Luggage. В зависимости от декларации есть два сценария:

| Декларация | Действие |
|---|---|
| Есть поле `into` | Поле получает имя назначения; программу не освобождают от создания или выбора файла и записи результата. |
| Нет `into` | Оболочка разрешает имя файла либо создаёт файл и передаёт `screen #ID`; обычный вывод BoxLib добавляется в конец файла. |

Текстовая стрелка не обрезает существующий файл. Вывод буферизуется,
цветовые метаданные не записываются. Обычное завершение сбрасывает буфер;
аварийное завершение может потерять ещё не записанные байты.
При отказе записи BoxLib сообщает об этом и направляет дальнейший вывод
на экран. Поэтому само наличие `screen #ID` не доказывает успешную запись.

### `form_screen_file`

**Краткое описание:** Узнайте, направлен ли обычный вывод программы в файл.

**Параметры:** Нет; объявление — `file_id_t form_screen_file(void)` в `box/form.h`.

**Возвращает:** `file_id_t`: идентификатор из `screen #ID` либо `0`.

**Побочные эффекты:** Сохраняет результат разбора Luggage для последующих обращений.

**Как работает:** Читает записи Luggage без запуска заполнителя и без вопросов. Для неверного, повторного или незавершённого указания возвращает `0`. Сам метод не открывает и не создаёт файл.

**Примечания:** Идентификатор описывает заданное направление вывода, а не текущее состояние файловой записи. Полноэкранная программа должна проверить его и выбрать текстовое представление результата вместо захвата экрана под стрелкой.

**Типичное применение:** Проверяйте перед созданием полноэкранного интерфейса Painter.

**Пример:**

```cpp
#include "box/form.h"

bool WantsTextOutput() { return form_screen_file() != 0; }
```

### `form_person_here`

**Краткое описание:** Проверьте, обозначила ли запускающая сторона присутствие человека перед программой.

**Параметры:** Нет; объявление — `bool form_person_here(void)` в `box/form.h`.

**Возвращает:** `bool`: присутствует ровно одна корректная запись `here`.

**Побочные эффекты:** Нет внешних; читает Luggage.

**Как работает:** Ищет признак среди NUL-завершённых записей. Он не проверяет физическое присутствие человека и не устанавливает владение клавиатурой. Оболочка добавляет запись при запуске программы на экране, но не при обычном фоновом запуске.

**Примечания:** Не ожидайте ответа на интерактивный вопрос только потому, что у программы существует экран. Без `here` вызывающая сторона не обещала возможность такого ответа.

**Типичное применение:** Проверяйте перед дополнительным вопросом, который программа решила задать уже после запуска.

**Пример:**

```cpp
#include "box/form.h"

bool MayAskPerson() { return form_person_here(); }
```

Сообщения для человека можно писать через `print_to_screen()` или
`print_bytes_to_screen()`, обходя текстовое перенаправление. Это подходит
для запроса и объяснения отказа; собственно результат оставляйте
обычному каналу вывода.

## Что находится в Luggage

Схема заполненного запуска:

```text
строка команды без стрелки\0
filled 1\0
field things\0
#41\0
#42\0
field words\0
=urgent\0
souvenir\0
here\0
```

Здесь `\0` обозначает байт NUL, а переносы строк добавлены только для
читаемости. Это не текстовый файл со строками LF.

`field KIND` начинает поле в порядке декларации; `#ID` — идентификатор
файла, `=TEXT` — одна строка значения. Необязательное пустое поле всё
равно имеет запись `field KIND`, но не имеет элементов.
`screen #ID`, `souvenir`, `here` — отдельные служебные записи.

Декодер проверяет версию, окончания записей, порядок и виды полей,
количество элементов одиночных полей, непустоту обязательных и отсутствие
повторных служебных указаний. Неизвестные записи заполненной Form
отвергаются; это строже пропуска неизвестных строк самой декларации.

Не собирайте этот буфер ручной конкатенацией для обычного запуска:
используйте `form_fill_luggage()`, учитывающий размеры и структуру.
`luggage_word()` и `luggage_tail()` читают обычную часть строки;
они не заменяют типизированное чтение полей Form. Стартовый `main()`
не получает эти данные как `argc`/`argv`.

## Интерфейс запускающей стороны

Для оболочек, Itinerary и собственных запускателей доступен C-интерфейс:

| Этап | Функции и ответственность |
|---|---|
| Прочитать декларацию | `form_of_file()` или `form_parse()` заполняют `BoxForm`; после работы вызывается `form_release()`. |
| Подготовить поиск | `form_lookup_volume()` создаёт поиск; запускающий добавляет свои `Them`, `ThemCount`, `ThemKnown`, `Given`. |
| Начать заполнение | `form_fill_begin()` получает декларацию, строку после имени программы и `BoxFormLookup`. |
| Продвигать разбор | `form_fill_step()` возвращает очередное состояние. |
| Ответить на вопрос | `form_fill_choose()`, `form_fill_words()`, `form_fill_sure()`. |
| Прочитать результат заполнения | `form_fill_field()`, `form_fill_arrow()` после `DONE`. |
| Обозначить условия запуска | `form_fill_program()`, `form_fill_souvenir()`, `form_fill_here()`. |
| Получить байты | `form_fill_luggage()` создаёт буфер, который вызывающий освобождает через `free()`. |
| Завершить | `form_fill_end()` освобождает заполнитель. |

Состояния: `BOX_FORM_DONE`, `BOX_FORM_ASK_WHICH`, `BOX_FORM_ASK_FIELD`,
`BOX_FORM_ASK_SURE`, `BOX_FORM_REFUSED`. Значение `form_fill_step() == 0`
само по себе не означает `DONE`: состояние находится в `Question.Step`.
Отрицательный результат — ошибка интерфейса или ресурсов.

При `REFUSED` повторный шаг остаётся отказом. После ответа на вопрос
нужно снова вызвать шаг. Декларация и описание поиска живут дольше
заполнителя; указатели в вопросе и полученные поля не сохраняйте
после следующего вызова или уничтожения заполнителя без копирования.

После `DONE` запускатель при необходимости создаёт файл стрелки,
передаёт его идентификатор в `form_fill_luggage()` и использует реальный
интерфейс запуска процесса с полученными байтами. Сам заполнитель
не запускает программу и не предоставляет отдельного процесса ожидания.
