# Souvenir — файлы результата программы

## Назначение

Souvenir — способ передать вызывающей стороне файлы, которые программа
считает своим результатом. Передаются идентификаторы TagFS, а не байты
файлов, пути или строки с их именами.

Это могут быть созданные файлы, изменённые исходные файлы или уже
существующие файлы, выбранные программой. Souvenir не требует создания
нового объекта и не передаёт исключительное владение файлом.

Оболочка сохраняет полученный набор для следующей команды как `them`.
`it` означает один файл этого набора. Так команды могут последовательно
работать с результатом предыдущей, не заставляя человека заново называть
файлы или разбирать текстовый вывод.

[Form](form.md) объявляет `gives things`, Souvenir выполняет передачу.
Объяснение результата на экране и передача его идентификаторов — разные
действия: напечатанное имя само по себе не становится Souvenir.

## Участники и условия передачи

Участвуют программа-отправитель, процесс, который её запустил, и его
Strand, обслуживающий сообщения результата. Получатель определяется
как `CabinInfo.spawner_pid`; пользователь функции отправки не выбирает
произвольный адресат.

Передача выполняется только при наличии отдельной записи `souvenir`
в Luggage. Эта запись означает, что запускающая сторона ожидает
и будет собирать файловый результат.

Штатная оболочка устанавливает признак, когда Form программы содержит
`gives things` и перенаправление не превратило её экран в файл.
Программа, запущенная другим приложением, не должна предполагать,
что запрос Souvenir появился автоматически: запускатель обязан
подготовить его явно.

```text
Form: gives things
        ↓ оболочка решила сохранить файловый результат
Luggage: souvenir
        ↓ программа получила идентификаторы результата
box::form::souvenir(Ids)
        ↓ IPC запускающей стороне
souvenir_collect(Pid, ...)
        ↓ обработка завершения команды оболочкой
them / it для следующей команды
```

Декларация результата не создаёт файлы, не заставляет программу вызвать
отправку и не подтверждает, что она успешно закончилась. Программа
решает, какие файлы передавать и в какой момент работы.

## Пример программы на C++

Пример возвращает вызывающей стороне те же файлы, которые получил.
Он ничего не создаёт и не изменяет; это законченный пример протокола,
показывающий, что результат может ссылаться на существующие объекты.

```cpp
#include "box/cxx/form.h"
#include "box/print.h"

BOX_FORM("takes things \"the files to give back\"\n"
         "gives things\n");

int main()
{
    auto Files = box::form::things(0);
    if (!Files) {
        print_to_screen("Cannot read the files field.\n");
        return 1;
    }

    auto Sent = box::form::souvenir(*Files);
    if (!Sent) {
        print_to_screen("Cannot send the file result.\n");
        return 1;
    }
    return 0;
}
```

Если учебная команда называется `returnfiles`, после
`returnfiles a.txt, b.txt` оболочка сможет использовать эти файлы
в следующей команде через `them`. Для `it` при нескольких результатах
потребуется выбор. Добавление исходника в сборку описано в
[первой программе на C++](first-program.md).

В программе, создающей результат, сначала выполните запись и нужные
проверки TagFS, затем отправляйте идентификатор. Сам Souvenir не
сохраняет содержимое и не выполняет операцию закрепления данных на носителе.

## Интерфейс отправителя

### `box::form::souvenir`

**Краткое описание:** Передайте вызывающей стороне идентификаторы файлов результата.

**Параметры:**

- `ids` (`std::span<const file_id_t>`, in): диапазон идентификаторов.

**Возвращает:** `box::status`: успех либо ошибка BoxOS.

**Побочные эффекты:** Может выделить временный буфер и отправить одно или несколько IPC-сообщений процессу, запустившему программу.

**Как работает:** C++-обёртка вызывает `souvenir_things(ids.data(), ids.size())` и преобразует отрицательный код в `box::error`. При отсутствии запроса в Luggage, нулевом spawner или пустом диапазоне низкоуровневая функция ничего не отправляет и сообщает успех.

**Примечания:** Успех не доказывает, что получатель прочитал результат. Исчезновение получателя с `ERR_PROCESS_NOT_FOUND` также считается отсутствием адресата, а не ошибкой работы программы. Метод `noexcept`; сам объект `std::span` не владеет файлами и не сохраняется функцией.

**Типичное применение:** Вызовите после успешного формирования результата, до выхода из программы. Повторные успешные вызовы добавляют файлы к переданному набору, не заменяют предыдущий.

**Пример:**

```cpp
#include <array>
#include "box/cxx/form.h"

box::status GiveResult(file_id_t File)
{
    const std::array<file_id_t, 1> Files{File};
    return box::form::souvenir(Files);
}
```

### `souvenir_things`

**Краткое описание:** Отправьте массив файлов результата через C-интерфейс.

**Параметры:**

- `ids` (`const file_id_t *`, in): начало массива; при `count > 0` не должно быть `nullptr`.
- `count` (`size_t`, in): число идентификаторов.

**Возвращает:** `int`: `0` при успехе или отсутствии требуемой передачи, отрицательный `-error_t` при ошибке.

**Побочные эффекты:** Выделяет и освобождает временный буфер; при требуемой передаче добавляет сообщения получателю.

**Как работает:** Функция проверяет указатель, наличие spawner, непустоту списка и признак `souvenir` в Luggage. Затем разбивает список на части, записывает заголовок и идентификаторы и вызывает `send()` для каждой части. Временный буфер переиспользуется и освобождается перед возвратом.

**Примечания:** `nullptr` с ненулевым количеством даёт `-ERR_INVALID_ARGUMENT`, нехватка буфера — `-ERR_NO_MEMORY`; прочие ошибки передачи возвращаются из `send()`, кроме `ERR_PROCESS_NOT_FOUND`. Функция не открывает файлы, не проверяет их существование и не удаляет повторы. Передавайте действительные идентификаторы, смысл которых определён операцией программы.

**Типичное применение:** Используйте напрямую из C; в C++ предпочтительна обёртка с `std::span`.

**Пример:**

```cpp
#include "box/form.h"

int GiveOne(file_id_t File)
{
    return souvenir_things(&File, 1);
}
```

## Что означает успех и ошибка отправки

| Ситуация | Результат |
|---|---|
| Пустой список | Успех, без сообщения. |
| Нет spawner | Успех, без сообщения. |
| Запускатель не запросил Souvenir | Успех, без сообщения. |
| Получатель исчез, `send()` вернул `ERR_PROCESS_NOT_FOUND` | Отсутствие получателя не превращается в ошибку отправки результата. |
| Все требуемые сообщения поставлены в очередь | Успех; чтение получателем ещё не подтверждено. |
| Ошибка выделения или другая ошибка `send()` | Отрицательный код или ошибка `box::status`. |

Несколько сообщений не образуют транзакцию. Если ранние части уже
отправлены, а следующая завершилась ошибкой, получатель может иметь
начало результата. Повтор всей отправки после ошибки может повторить
уже переданные идентификаторы.

Souvenir не содержит операции «заменить предыдущий результат»,
подтверждения приёма или отката. Для обычной команды удобно подготовить
окончательный набор и отправить его одним вызовом. Его размер всё равно
может потребовать нескольких IPC-сообщений.

Исходный массив требуется только на время вызова. При последовательных
вызовах файлы идут в порядке передачи; при одновременной отправке из
нескольких Strand общий порядок приложению нужно определить отдельно.

## Как оболочка сохраняет результат

При завершении запущенной программы Strand обслуживания `hub/jobs.cpp`
вызывает `souvenir_collect()` для её PID. Сообщения собираются даже если
впоследствии результат не будет сохранён: старые сообщения не должны
остаться для случайного будущего сбора.

Выбор результата:

| Условия запуска | Что оболочка сохраняет |
|---|---|
| Экран был направлен в файл | Этот файл, независимо от декларации файлового результата. |
| Souvenir был запрошен и собран | Полученный список, включая пустой. |
| Ни того ни другого | Новый набор файлов результата не назначается. |

Для завершившейся команды перед человеком `launch::Settle()` записывает
этот результат в `Self.Given`. Пустой собранный Souvenir означает
известный пустой результат и может заменить прежний `them`.
Если новый файловый результат не назначен, прежний набор сам по себе
не обязан очищаться.

Сохранение уже переданных файлов в этом пути не зависит только от
нулевого кода завершения: оболочка отдельно сообщает исход выполнения.
Souvenir может содержать файлы, переданные до отказа или аварии.
Поэтому он не служит отдельным подтверждением успешности всей команды.

Фоновые программы и программы, отпущенные с экрана, имеют другой момент
завершения относительно следующей введённой команды. Не рассчитывайте,
что их запоздалый результат автоматически заменит текущий `them` так же,
как у обычной команды, которую оболочка дождалась перед человеком.

### `them` и `it`

`them` означает весь сохранённый набор; `it` — один его элемент.
Если элементов несколько, заполнитель Form задаёт вопрос выбора.
Повторяющиеся ссылки могут быть устранены уже при заполнении конкретного
файлового поля, но передача и сбор Souvenir сами не выполняют дедупликацию.

Это состояние конкретной оболочки, а не глобальная таблица ядра.
Оно не переносится в каждую новую программу как самостоятельный Souvenir:
оболочка использует его при подготовке следующих полей Form.

## Связь с перенаправлением ->

Если программа не имеет поля `into`, `command -> out.txt` делает
файл направлением её обычного вывода. Оболочка сохраняет этот файл
как результат, поэтому не запрашивает отдельный Souvenir даже при
декларации `gives things`.

Если в Form есть `into`, имя после стрелки передаётся этому полю.
Программа сама создаёт или выбирает файл и записывает результат.
При `gives things` она возвращает соответствующий идентификатор через
Souvenir; автоматического создания файла только из объявления `into` нет.

| Действие программы | Является Souvenir |
|---|---|
| Напечатать имя файла | Нет. |
| Вывести текст, который оболочка собирает через `->` | Нет отдельного Souvenir; результатом оболочки становится файл вывода. |
| Создать файл и завершиться | Нет, пока идентификатор не отправлен или результат не определён другим предусмотренным путём. |
| Передать существующий файл через `box::form::souvenir()` | Да, если получатель запросил передачу. |

## Получение в собственном запускателе

Запускатель должен выполнить обе стороны соглашения:

1. Прочитать и заполнить Form программы.
2. После `DONE` вызвать `form_fill_souvenir()` и сформировать Luggage
   через `form_fill_luggage()`.
3. Запустить ребёнка с этими байтами и сохранить его идентичность.
4. Наблюдать завершение предусмотренным интерфейсом процессов.
5. На Strand, которому приходят ответы этого запуска, собрать Souvenir.
6. Освободить полученный массив после использования.

Обычный запуск по строке не обещает подготовить запрос за приложение.
Само ожидание ребёнка также не выполняет сбор Souvenir автоматически.
Пробуждение о завершении и файловый результат — разные данные.

### `souvenir_collect`

**Краткое описание:** Соберите ожидающие сообщения файлового результата указанного отправителя.

**Параметры:**

- `from_pid` (`uint32_t`, in): PID программы, чей Souvenir требуется.
- `ids` (`file_id_t **`, out): адрес переменной для выделенного массива.
- `count` (`size_t *`, out): адрес переменной для числа идентификаторов.

**Возвращает:** `int`: `0` при успешном сборе, отрицательный `-error_t` при ошибке; пустой результат — `*ids == nullptr`, `*count == 0`.

**Побочные эффекты:** Читает текущую очередь результатов, выделяет временные массивы и массив результата; снимает принятые сообщения Souvenir и возвращает их память через `give_back()`.

**Как работает:** Функция неблокирующим `receive()` временно собирает ожидающие сообщения. Она выбирает сообщения указанного PID с корректными magic, количеством и длиной, копирует идентификаторы в общий массив и возвращает остальные сообщения в локальное хранилище результатов. При отказе выделения собранные сообщения возвращаются без принятия Souvenir.

**Примечания:** `ids` и `count` обязательны. При успехе вызывающий владеет массивом и освобождает его `free()`. Функция не ждёт будущих сообщений и не ожидает завершения процесса. Вызывайте её после подтверждённого завершения: по контракту `send()` сообщения уже поставлены в очередь до наблюдаемого завершения отправителя. Фильтр этой функции использует PID, а не пару PID/поколение; своевременный сбор и учёт точного запущенного процесса остаются обязанностью запускателя.

**Типичное применение:** После события завершения соберите результат на обслуживающем Strand, обработайте список и освободите массив. Не запускайте одновременно конкурирующий потребитель той же очереди без определённого разделения ответственности.

**Пример:** Функция ниже предполагает, что завершение ребёнка уже подтверждено. Она копирует результат в `std::vector`, а исходный массив освобождает при любом выходе, включая исключение выделения памяти вектора.

```cpp
#include <memory>
#include <vector>

#include "box/cxx/error.h"
#include "box/form.h"
#include "box/memory.h"

box::result<std::vector<file_id_t>> CollectAfterExit(std::uint32_t Pid)
{
    file_id_t *Raw = nullptr;
    std::size_t Count = 0;
    const int Rc = souvenir_collect(Pid, &Raw, &Count);
    if (Rc < 0) return std::unexpected(box::error{box_errno_of(Rc)});

    const std::unique_ptr<file_id_t, decltype(&::free)> Held(Raw, &::free);
    std::vector<file_id_t> Files;
    if (Count != 0) Files.assign(Raw, Raw + Count);
    return Files;
}
```

Сбор опустошает уже найденные сообщения результата. Повторный вызов
после завершения обычно вернёт пустой список. Если вызвать его слишком
рано, пустой список означает лишь отсутствие сообщений сейчас.

## Представление сообщения

Реализация находится в `form_souvenir.c`. Один пакет содержит:

| Смещение | Размер | Тип | Назначение |
|---|---|---|---|
| `0` | 4 | `uint32_t` | `SOUVENIR_MAGIC = 0x56554F53`, байты `53 4F 55 56` на x86-64. |
| `4` | 4 | `uint32_t` | Количество идентификаторов в этом сообщении. |
| `8` | `Count × 8` | `file_id_t[]` | Идентификаторы TagFS. |

Внешний IPC `Result` содержит PID отправителя, адрес и длину данных.
Получатель требует, чтобы длина после заголовка была кратна 8 и точно
совпадала с указанным количеством.

У `send()` длина представлена `uint16_t`. Поэтому максимум этого
кодирования — `(65535 - 8) / 8 = 8190` идентификаторов на сообщение,
то есть 65528 байт вместе с заголовком. Больший список разбивается.
Это предел одного пакета, а не общего количества результата.
Доступная память и ограничения IPC продолжают действовать.

В пакете нет номера версии, порядкового номера части, общего количества,
флага «последний», кода завершения или идентификатора транзакции.
Граница полного результата определяется завершением программы и
последующим сбором очереди, а не отдельным завершающим сообщением.
Штатная отправка пустого списка вообще не создаёт пакет.

Это внутренний протокол текущей реализации BoxLib для x86-64,
а не часть бинарной таблицы `.box`. `gives things` хранится в Form
исполняемого файла; сами пакеты существуют только во время выполнения.

## Границы ответственности

Souvenir не проверяет существование, теги или сохранность файлов.
Получатель должен обрабатывать отказ последующего чтения: объект мог
измениться или стать недоступным. Передача идентификатора не создаёт
копию содержимого и не закрепляет прежнее состояние файла.

Набор возвращённых файлов не является владением в смысле `unique_ptr`:
освобождение массива идентификаторов не удаляет файлы TagFS.
Существование массива, IPC-сообщения и файлов — три разных срока жизни.

Для произвольного обмена данными, длительного потока сообщений или
запроса с ответом выбирайте соответствующий интерфейс IPC/Current.
Souvenir предназначен для файлового результата запущенной операции.
