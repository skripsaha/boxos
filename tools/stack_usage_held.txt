# tools/stack_usage_held.txt — what the stack guard holds, and until when.
#
# Every line is a Caveat: a defect this tree still has, measured, named, and
# given the step of the Quill plan that removes it. While the defect is there
# tools/check_stack_usage.py says "caveat held" and the kernel is linked. When
# it is gone the line is a FAILURE until it is deleted — in the same commit as
# the step that removed it, which is how this file only ever gets shorter.
#
# A function line: <source>:<function>  <bytes>  <step>  <what the frame holds>
#   bytes are GCC 15.2.0's, default build keys; the frame may not grow past
#   them, and falling to 1024 or under lifts the caveat.
# The reach line:  reach  <bytes>  <step>  <the chain>
#   the heaviest chain from a storage request to the medium; it may not grow,
#   and falling to the budget (4096) lifts the caveat.
#
# Measured 2026-09-27 at e7aa9345. At 1.6 the mount's read of the volume left
# tagfs_init for mount/ and its census reads no block — the owners answer from
# memory — so tagfs_init's frame and ledger_read_copy's second sector are gone.
# At 1.9 the DiskBook's two mount frames went: the book is read once, by the
# mount that names the snapshots an earlier kernel left, its head and each
# record in turn through one record's room in the heap.
# The reach measured again 2026-09-28, at 9616: the integrity map pages
# through its slots' own buffers now, so no block of it is on the stack; and
# again at 1.3, at 9456, once no write asked copy-on-write for a snapshot; and
# at 1.3's Plot, at 5456: a write's block, a defrag's copy and a record's CRC
# check are in the heap now, and meta_pool_delete's is the one block left; and
# at 1.4, at 4568: the pool is only appended to in memory and written by the
# Settle cycle from its own buffer, so the read-ahead's block was the one left.
# At 1.10 the read-ahead fetches into its handle's window from the heap, and
# the reach fell within its budget: its line is gone, and the budget holds it.
